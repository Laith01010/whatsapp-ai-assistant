# WhatsApp AI Assistant for a Medical Fitness Center

An AI-powered WhatsApp bot that answers customer questions for a (fictional) visa medical fitness center — in **Arabic and English** — using only the center's own information, and hands the conversation to a human when needed.

Built with **n8n**, the **WhatsApp Cloud API (Meta)** and **Google Gemini**.

> 🇸🇦 Step-by-step setup guide in Arabic: [`docs/SETUP_AR.md`](docs/SETUP_AR.md)

---

## Why

Service centers like this receive hundreds of WhatsApp messages a day, and most of them are the same few questions: required documents, prices, working hours, how long results take. Staff spend hours copy-pasting answers. This bot answers those instantly, around the clock, and only involves a person when it actually matters.

## What it does

- Replies in the customer's language (Arabic or English)
- Answers **only** from a knowledge base — it does not invent prices, times or policies
- Remembers the recent conversation, so follow-ups like *"and how long does that take?"* work
- Hands off to a human (and alerts a staff member on WhatsApp) when the customer asks for one, complains, asks about their result status, or asks something the knowledge base doesn't cover
- Asks customers to type when they send images or voice notes
- Never gives medical advice or interprets results

## Architecture

```
Customer ──► WhatsApp Cloud API ──► n8n Webhook
                                        │
                                  Parse Message      filter events, de-duplicate, load history
                                        │
                                  Ask Gemini         answer from the knowledge base only
                                        │
                                  Process Reply      clean reply, save history, detect hand-off
                                        │
                                  Send WhatsApp Reply ──► Customer
                                        │
                                  Needs Human? ──yes──► Notify Staff (WhatsApp alert)
```

A separate `GET` webhook handles Meta's one-time verification handshake.

## Design decisions

| Decision | Reason |
|---|---|
| Webhook responds `200` immediately | Meta retries slow webhooks, which would cause duplicate replies |
| De-duplication by message ID | Even if Meta re-delivers, the customer gets one answer |
| Status events (delivered/read) ignored | They arrive on the same webhook but aren't messages |
| Strict system prompt + knowledge base | Keeps answers grounded; unknowns go to a human |
| `[HANDOFF]` tag from the model | The model decides when a person is needed; the tag is stripped before sending |
| Short conversation memory (6 turns, 24h) | Enough for follow-ups without growing unbounded |
| Graceful fallback on AI errors | Customer gets a polite reply, staff get an alert — never silence |
| `gemini-3.5-flash-lite` | Fast and inexpensive for high-volume FAQ traffic; swappable in one line |

## Project structure

```
whatsapp-ai-bot.n8n.json   importable n8n workflow (generated by build.js)
nodes/
  parse-message.js         config, knowledge base, prompt, webhook parsing
  process-reply.js         reply handling, memory, hand-off
  verify-token.js          Meta webhook verification
build.js                   builds the workflow JSON from the node sources
test.js                    simulates the n8n Code nodes and checks the logic
sample-message.json        sample WhatsApp webhook payload for testing
docs/SETUP_AR.md           full setup guide (Arabic)
```

The Code node logic lives in plain `.js` files so it can be version-controlled and tested outside n8n.

## Run the tests

```bash
node test.js
```

Covers: webhook verification, request building, duplicate and status-event filtering, conversation history, hand-off detection, API failure fallback, and workflow integrity.

## Setup (short version)

1. Import `whatsapp-ai-bot.n8n.json` into n8n.
2. Get a Gemini API key from Google AI Studio.
3. Create a Meta app with the WhatsApp use case and grab the **Phone Number ID** and an **access token**.
4. Fill in `CONFIG` in the **Parse Message** node, then publish the workflow.
5. In Meta, set the webhook callback to the n8n production URL, use the verify token from the **Verify Token** node, and subscribe to `messages`.
6. Subscribe the WhatsApp Business Account to the app (one-time):
   ```bash
   curl -X POST "https://graph.facebook.com/v26.0/<WABA_ID>/subscribed_apps" \
     -H "Authorization: Bearer <TOKEN>"
   ```

Full walkthrough with troubleshooting: [`docs/SETUP_AR.md`](docs/SETUP_AR.md).

## Taking it to production

This is a working demo. For a real deployment I would add:

- Business verification, a real number and a permanent **System User** token
- Paid AI tier so customer data isn't used for model training
- Credentials stored in n8n Credentials, not in code
- Conversations stored in a database / CRM instead of workflow memory
- Integration with the center's appointment and results systems
- A shared inbox for staff to take over conversations
- Approved message templates for outbound notifications (e.g. "your result is ready")
- Monitoring, retries and reporting (top questions, hand-off rate)
